## 3. Банк вопросов по Проекту №0 (`taskflow-cli-core`) — готовиться заранее

> Формат: вопрос → что именно хочет услышать интервьюер → каркас ответа. Заполнять после реализации каждого слоя.

1. **Почему `dataclasses`, а не Pydantic или обычные классы?** → Ожидание: понимание, что dataclass даёт `__init__/__repr__/__eq__` бесплатно, но **не валидирует** данные; Pydantic валидирует на границе входа. Ответ для CLI: dataclass + явная валидация в `__post_init__`.
2. **Зачем слои `storage` / `service` / `cli`?** → Separation of concerns, тестируемость без файловой системы, возможность заменить JSON на PostgreSQL, не трогая бизнес-логику (Dependency Inversion).
3. **Что будет, если процесс убьют во время записи JSON?** → Повреждение файла. Решение: атомарная запись — пишем во временный файл в той же директории, `os.replace()` (атомарен в пределах одной ФС), при желании `fsync`.
4. **Как ты тестируешь работу с файлами?** → Фикстура `tmp_path` от pytest, изоляция каждого теста, никаких записей в репозиторий.
5. **Почему `logging`, а не `print`?** → Уровни, формат, вывод в stderr vs stdout, возможность писать в файл и в JSON-структуру для агрегаторов, отключение в тестах.
6. **CLI: `argparse` или `click` — почему?** → argparse в стандартной библиотеке, ноль зависимостей; click удобнее для больших CLI и даёт декларативные подкоманды. Обосновать выбор под задачу.
7. **Как реализовать отчёт по затраченному времени без O(n²)?** → Один проход + `defaultdict`/`Counter`, предподсчёт агрегатов; сложность O(n) по времени, O(k) по памяти.
8. **Переходы состояний задачи: как запретить `done → todo`?** → Конечный автомат: словарь допустимых переходов, исключение `InvalidTransitionError`.
9. **Что в твоём CI и почему именно это?** → ruff (скорость, замена flake8+isort), pytest с coverage, триггеры `push`/`pull_request`, матрица версий Python.
10. **Какое самое слабое место архитектуры и что бы ты переделал?** → Честный ответ про файловое хранилище (конкурентный доступ, отсутствие блокировок, O(n) на чтение всего файла) и план миграции на SQLite/PostgreSQL.

**Пробелы, которые закроет Проект №1:** async, SQL, индексы, Docker, Redis, auth. **Пробелы Проекта №2:** LLM API, векторный поиск, guardrails.
