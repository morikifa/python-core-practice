# Архитектурное и техническое ревью: taskflow-cli-core

**Дата ревью:** 05.09.2026  
**Статус:** Отклонено до устранения дефектов P0 (Gate blocked).  
**Тестовый прогон:** 22 зонда подтвердили 22 архитектурных и логических дефекта.

## 1. Сводка критических дефектов (C1–C6)
- **C1 (Lost Update):** Отсутствие блокировки `fcntl.flock` при конкурентном доступе (read-modify-write) приводит к тихой потере данных при параллельном вызове из нескольких процессов (например, cron + терминал).
- **C2 (Durability / fsync):** `flush()` сбрасывает данные только в страничный кэш ядра ОС, но не на физический накопитель. Без `os.fsync(fd)` и синхронизации каталога гарантия защиты от сбоя питания отсутствует.
- **C3 (Exception Swallowing):** `except Exception` маскирует ошибки доступа `PermissionError` (Errno 13) под `StorageCorruptedError`, вводя пользователя в заблуждение.
- **C4 (Permissions Degradation):** `NamedTemporaryFile` по умолчанию создает файл с правами `0o600`, а `Path.replace()` переносит inode вместе с этими правами, ломая доступ для других процессов (`0o644`).
- **C5 (Coercion Trap):** Использование `str()` уничтожает валидацию типов (`None` превращается в строку `'None'`, `id=12345` в `'12345'`), а невалидный Enum выбрасывает `ValueError` мимо иерархии `TaskFlowError`.
- **C6 (Missing Domain Feature):** Отсутствие сущностей учета времени (`TimeEntry`, замеры продолжительности, сессии). Проект скатился в обычный todo-лист.

## 2. План доработки P0 (после сдачи экзамена Т-Банка, 07–10.09)
1. Внедрить сущности тайм-трекинга (`TimeEntry`, методы `start`/`stop`/`duration`).
2. Добавить `fcntl.flock` (блокировка файла на чтение/запись).
3. Добавить `os.fsync` для дескриптора временного файла и дескриптора каталога.
4. Разделить `except (json.JSONDecodeError, UnicodeDecodeError)` и `except PermissionError`.
5. Использовать строгие `isinstance`-проверки вместо коэрции `str()`.
6. Добавить версионирование схемы хранения `schema_version = 1`.
