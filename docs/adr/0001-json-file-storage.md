# ADR 0001: Выбор атомарного JSON-хранилища на базе pathlib для TaskFlow CLI Core

**Статус:** Принято  
**Дата:** 05.09.2026  
**Автор:** Матвей (@morikifa)

---

## 1. Контекст и проблематика
Для первого проекта линейки (`taskflow-cli-core`) требовалось автономное, легковесное, кроссплатформенное хранилище без необходимости поднимать внешние серверы баз данных (PostgreSQL/MySQL). 

Рассматривались альтернативы:
1. **SQLite (`sqlite3`):** встроенная реляционная БД.
2. **Plain JSON с перезаписью (`open("w")`):** простое текстовое хранилище.
3. **Атомарный JSON через временные файлы (`NamedTemporaryFile` + `replace()`):** решение с защитой от race conditions и повреждения данных.

## 2. Принятое решение
Использовать подход **Atomic JSON Storage** с использованием модуля `pathlib.Path` и `tempfile.NamedTemporaryFile`.
- Все записи происходят во временный файл в той же файловой системе.
- После сброса буфера (`flush()`) временный файл атомарно подменяет основной файл методом `os.replace` (`Path.replace`).
- Это гарантирует невозможность повреждения (corruption) JSON при аварийном завершении процесса во время записи.

## 3. Последствия
### Положительные:
- Нулевые внешние зависимости.
- Файл данных читаем человеком (`json.dump(indent=2)`).
- 100% защита от полузаписанных файлов.

### Отрицательные / Ограничения:
- Не подходит для $10^6+$ записей (требует полной вычитки файла в RAM). Для масштабирования в следующих проектах будет использован PostgreSQL.
