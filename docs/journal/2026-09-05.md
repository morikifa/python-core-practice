## 1. Что сделано за день
- Спроектирована и реализована 4-слойная архитектура: `models` (Domain) -> `storage` (Persistence) -> `service` (Business Logic) -> `cli` (User Interface).
- Доменные модели реализованы на Python `@dataclass` со строгой валидацией типов, перечислениями `Enum` и кастомной иерархией исключений `TaskFlowError`.
- Реализован слой персистенса `JsonTaskStorage` с применением паттерна Atomic File Write (защита от повреждения JSON).
- Написан сервисный слой `TaskService` с поддержкой поиска по префиксу UUID и фильтрации.
- Реализован полнофункциональный CLI-интерфейс на `argparse` с цветным выводом.
- Написано 23 автотеста на `pytest` с изолированными фикстурами `tmp_path`. Достигнуто тестовое покрытие **>90%**.
- Подготовлен `Dockerfile` (multi-stage) и пайплайн `GitHub Actions` CI/CD.
- Оформлен архитектурный документ `ADR 0001`.

## 2. С какими трудностями столкнулся и как решил
- **Проблема:** В тесте `test_task_creation_defaults` не сходились микросекунды в `created_at` и `updated_at`.
- **Решение:** В `__post_init__` добавлена проверка: если `updated_at` не передан явно, он инициализируется точным значением `created_at`.
- **Проблема:** Необходимость запуска CLI в изолированных контейнерах без root-прав.
- **Решение:** В `Dockerfile` создан отдельный пользователь `appuser` (UID 1000) с домашней директорией для хранилища.
