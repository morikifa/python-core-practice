## Формат работы с каждой задачей

1. Создать файл `algorithms/<тема>/task_XX.py`.
2. В docstring: условие, ограничение входа, **оценка O(время) и O(память)**, дата.
3. Чтение входа: `sys.stdin.readline()` (быстрее `input()` на больших объёмах).
4. Внизу файла — `if __name__ == "__main__":` с вызовом `main()`.
5. Минимум 3 своих теста на edge cases: пустой вход, 1 элемент, максимум, отрицательные/нули, дубликаты.
6. Запустить вручную, убедиться, что вывод совпадает **точно** (пробелы, переводы строк).
7. Коммит: `feat(algo): task_03 two pointers pair sum` — по одной задаче на коммит.
8. После сдачи — отдать на ревью: сложность, edge cases, стиль, что можно улучшить.

**Жёсткое требование:** после решения назвать вслух сложность и объяснить, **почему** нельзя быстрее. Не смог объяснить → решение не засчитано.

## Задачи

### Тема 1. Префиксные суммы (`prefix-sums/`)

**task_01 — Сумма на отрезке.**
Дан массив из n целых чисел (n ≤ 10^5) и m запросов (m ≤ 10^5). Каждый запрос — пара индексов `l r` (0-based, l ≤ r). Вывести сумму элементов на отрезке [l, r] для каждого запроса, по одному числу в строке.
Ограничение по времени: 1 с. Наивное решение O(n·m) = 10^10 операций → TL.
Целевая сложность: O(n + m) время, O(n) память.

**task_02 — Количество подотрезков с суммой K.**
Дан массив целых чисел (возможны отрицательные, n ≤ 10^5) и число K. Посчитать количество непрерывных подотрезков, сумма элементов которых равна K.
Подсказка (не решение): сумма отрезка = разность префиксных сумм → ищи пары префиксов с разностью K. Какой тип данных хранит «сколько раз встречался каждый префикс»?
Целевая сложность: O(n) время.

### Тема 2. Два указателя (`two-pointers/`)

**task_03 — Пара с заданной суммой.**
Отсортированный по неубыванию массив (n ≤ 10^5) и число S. Найти **любые** два индекса i < j такие, что `a[i] + a[j] == S`. Вывести индексы через пробел или `-1`, если пары нет.
Запрещено: вложенные циклы, `list.index()`, бинарный поиск в цикле (это тоже O(n log n), но цель — O(n)).
Целевая сложность: O(n) время, O(1) память.

**task_04 — Сжатие строки.**
Строка из строчных латинских букв (длина ≤ 10^5). Заменить каждую группу одинаковых соседних символов на символ + количество, но **только если** количество > 1. Пример: `aaabcc` → `a3bc2`. `abcd` → `abcd`.
Edge cases: пустая строка, строка из одного символа, вся строка одинаковая.
Целевая сложность: O(n).

**task_05 — Палиндром с игнорированием мусора.**
Строка (≤ 10^5) содержит буквы, цифры, пробелы и знаки препинания. Определить, является ли она палиндромом, если учитывать только буквенно-цифровые символы и игнорировать регистр. Вывести `YES` / `NO`.
Целевая сложность: O(n) время, O(1) дополнительной памяти (два указателя без создания новой строки — если создаёшь отфильтрованную строку, честно напиши в docstring, что память O(n)).

### Тема 3. Словари и счётчики (`hashmaps/`)

**task_06 — Анаграммы в потоке.**
Дано n строк (n ≤ 10^5, длина каждой ≤ 100). Разбить их на группы анаграмм и вывести количество групп. Порядок строк внутри группы не важен.
Ключевой вопрос: что использовать как ключ словаря, чтобы анаграммы давали одинаковый ключ? Оцени сложность построения ключа.
Целевая сложность: O(n · k) где k — длина строки.

**task_07 — Первый неповторяющийся символ.**
Строка (≤ 10^5). Вывести индекс первого символа, который встречается в строке ровно один раз, или `-1`.
Запрещено: `s.count(c)` в цикле по всей строке — это O(n²).
Целевая сложность: O(n) время (два прохода), O(1)–O(Σ) память.

### Тема 4. Скользящее окно (`sliding-window/`)

**task_08 — Максимальная сумма K подряд.**
Массив целых чисел (n ≤ 10^5) и число K (1 ≤ K ≤ n). Найти максимальную сумму среди всех непрерывных подмассивов длины ровно K. Если K > n — вывести `-1`.
Целевая сложность: O(n) время, O(1) память. Наивный пересчёт суммы окна = O(n·K) → TL.

**task_09 — Самая длинная подстрока без повторяющихся символов.**
Строка (≤ 10^5). Найти длину самой длинной подстроки, в которой все символы различны.
Целевая сложность: O(n) время. Какая структура хранит «последнюю позицию каждого символа»?

### Тема 5. Стек (`stack/`)

**task_10 — Валидность скобочной последовательности.**
Строка из символов `()[]{}` (длина ≤ 10^5). Вывести `YES`, если последовательность корректна, иначе `NO`. Пустая строка — `YES`.
Edge cases: `[(])`, `(((`, `)`, одиночная открывающая в конце.
Целевая сложность: O(n) время, O(n) память.

### Тема 6. Симуляция (`simulation/`)

**task_11 — Очередь задач в обработчике.**
Обрабатываются задачи в порядке поступления. Каждая задача имеет `id`, момент поступления `t` и длительность `d`. Один обработчик. Если в момент `t` обработчик занят, задача ждёт в очереди (FIFO). Для каждой задачи вывести `id` и **момент окончания обработки**.
Вход: n (≤ 10^5), затем n строк `id t d`, отсортированы по неубыванию `t`.
Edge cases: несколько задач в один момент времени; нулевая длительность; большой разрыв между задачами (обработчик простаивает).
Целевая сложность: O(n). Что здесь моделирует очередь и нужно ли хранить её явно?

### Тема 7. Матрицы (`matrix/`)

**task_12 — Поворот матрицы на 90° по часовой.**
Квадратная матрица n×n (n ≤ 500). Вывести повёрнутую матрицу, строки через пробел.
Два способа: (а) дополнительная матрица — O(n²) памяти; (б) in-place: транспонирование + реверс каждой строки — O(1) памяти. Реализуй (б) и объясни в docstring, почему это эквивалентно повороту.
Целевая сложность: O(n²) время (каждый элемент посещён константное число раз).

## Шпаргалка по вводу-выводу для контеста (это не решение задач, это механика)

Быстрое чтение всех строк входа и быстрый вывод — единственная «заготовка», которую разрешено иметь под рукой:

- `import sys` → `data = sys.stdin.read().split()` даёт список всех токенов входа за один проход; дальше `map(int, data)` или индексация.
- Для построчного чтения: `sys.stdin.readline` (присвоить в локальную переменную, если читаешь в цикле — экономия на поиске атрибута).
- Вывод: накапливать результаты в список и один раз `sys.stdout.write("\n".join(map(str, res)))` — быстрее, чем `print` в цикле на 10^5 строк.
- Рекурсия: на глубине >1000 упадёт с `RecursionError` (лимит по умолчанию 1000). В контесте рекурсию не использовать или поднять лимит `sys.setrecursionlimit` **только если** действительно нужен обход в глубину; для задач выше рекурсия не нужна.
